# 不可能的任務｜Impossible Mission

> 手機只是工具，真正的冒險發生在人與人之間。

**專案狀態：第一關「保羅海難」可執行原型 v0.8（2026-11-16 加入重玩性：見聞、風暴捲走、三種用掉只來得及一件）；只有自動測試與模擬手機，尚未真人試玩。經文已用 tools/verify_verses.py 與新標點和合本逐字比對（見 docs/05）。**
**目標玩家**：青少年與成人、教會小組、第一次接觸聖經的朋友。
**設備**：每人一支手機，不用額外卡片與道具。

## 一句話玩法
3–10 人掃 QR Code 上同一條船——使徒行傳 27 章保羅搭的那艘運糧船。約 8 分鐘裡，大家交換手上的情報，決定風暴中**丟什麼、留什麼**；天黑時一起形容記號幫木匠補船；第十四天夜裡決定天亮前只來得及做的**一件事**（吃飯、拋錨或捆船底），天亮時衝向海灘。經文裡 276 人全都得救，遊戲也一樣；星星衡量的是上岸順不順。每局抽兩張「故事卡」（這章真的發生的事），而且**今晚靠哪一樣東西每局不同、只有某幾位隊友知道**（見聞），所以第十局還是要開口問。

## 團隊計分與排行榜（2026-11-16 使用者核准，試行；docs/13、ADR-0008）
- 每局由伺服器依團隊表現計分，滿分 1000：任務成果 600、合作順暢 200、時間 100、難度加成 100。分數標「試行」，**未經真人試玩**；只排團隊、與信仰和聖經答題無關。
- 首頁「🏆 排行榜」：一個總榜、不分人數、永不重置、前 10 名；同隊名只留最高分。結算畫面只有房主（且須是這局的隊員）能「登記上榜」（隊名最多 12 字、每局一次）；管理用 `setHidden` 可隱藏紀錄（不刪資料、無對外端點）。單機試玩（`/solo.html`）是練習房，不計入排行榜。
- API：`GET /api/leaderboard`；WebSocket `{t:'leaderboard'}`、`{t:'submitScore', name}`。
- 排行榜儲存：Node 版預設只在記憶體，設環境變數 `LEADERBOARD_FILE`（例：`data/leaderboard.json`）才存檔；Cloudflare 版存在 Durable Object 的 SQLite。
- 限制：同一台電腦開多個分頁假裝多人無法辨識；隊名可冒用。

## v0.9 失敗結局、力氣靠吃飯、全員同意（2026-11-20 使用者決定，DECISIONS 18、docs/14、ADR-0009）
- **可能沒能平安上岸**：顧好 0–1 件，或時間到還沒出發＝「這一局，你們沒能平安上岸」。不畫不寫有人死亡，結算一定寫「經文裡，船上 276 人全都上了岸」。
- **力氣只能靠吃飯**：食物留在船上不算（27:33「十四天沒吃」）；吃飯也佔「天亮前只來得及一件」。拿掉「大家吃不下」見聞。
- **全員同意**：決定好了、吃飯／拋錨／捆船底、衝向海灘，按下去後其他人跳出「同意／等一下／我有情報」；同一件事 2 次沒通過，負責人可以強制；10 秒沒回應算同意。
- 試算：176 種局面全部有三星解、都有不會失敗的帶法；照抄成功率 15.9%。**好不好玩、會不會拖慢、會不會讓人難過：未測試。**

## v0.8 重玩性（2026-11-16 使用者核准，docs/12、ADR-0007）
- **見聞**：伙房知道今晚吃糧食還是麥子、水手長／管倉知道捆船用哪條繩子、測水深／瞭望知道水深（醫生的「吃不吃得下」v0.9 拿掉）。只在自己手機上，要說出來。遊戲自創的細節標「遊戲設定」。
- **風暴捲走**：第二局起，危機一來，丟下海的東西就撈不回來；捲走前 10 秒所有手機提醒。首局不啟用。
- **天亮前只來得及一件**：吃飯（伙房）、拋錨（測水深／瞭望，水淺時）、捆船底（木匠），全隊只能做一件（v0.9 起吃飯也算，改成全員同意、沒有取消）。
- 試算：262 種局面全部有三星解；照抄上一局的三星打法只有 13.5% 還能三星（v0.7 是 100%）。**好不好玩、會不會太複雜：未測試。**

## v0.7 改進重點（2026-11-15 使用者決定）
- **聖經故事就是關卡**：第一關改編保羅海難（徒 27），取代原創暴風雨救援；拿掉「老智慧」。
- **故事卡**：起風卡、風暴卡各 5 張，都是經文裡的事件＋「所以這局……」，不是抽籤算命；25 種組合都經 `tools/verify_seeds.py` 試算可解。
- **不是你能按的，不顯示**：托盤只在管倉、「決定好了／衝向海灘」只在船長、「召集大家吃飯」只在伙房。資訊仍可互看。
- **圖代替字、能動就動**：船在浪中搖、東西拋進海裡、天色變暗、擘餅、擱淺上岸都是 SVG＋CSS 動畫（尊重 prefers-reduced-motion）。

## 已確定的原則
1. 現場真人討論、協調、交換手機觀看資訊；不能限制說話或觀看隊友畫面。
2. 手機顯示地圖、物資、倒數、突發事件與修復機關；停電只是遊戲內的 UI 遮罩。
3. 入房不計時、每局 5–10 分鐘；結束能接下一局。不強迫站立或分享隱私。
4. 聖經連結是自然引導，不是測驗，不用「信仰分數」評價人。

## 部署到網路（Cloudflare，任何網路都能玩）
目前網址：https://impossible-mission.next-calendar.workers.dev （2026-11-14 部署；只有模擬手機測過，未經真人試玩）

需要 Cloudflare 帳號。部署後會得到 `https://impossible-mission.<你的子網域>.workers.dev`，手機用行動網路掃 QR Code 就能加入（docs/adr/0005）。

```bash
npx wrangler deploy
```

想先試新版、不動正式網址：`npm run deploy:preview` 會部署到另一個獨立的 Worker `impossible-mission-preview`（網址為 `https://impossible-mission-preview.<你的子網域>.workers.dev`）。

第一次會要求登入或設定 `CLOUDFLARE_API_TOKEN`（Edit Cloudflare Workers 權限）。本機模擬 Cloudflare：`npm run dev:worker`。

## 在現場跑原型（未經真人試玩）
不想部署時的替代做法：需要 Node.js 22.18 以上，以及一台和手機連到**同一個 Wi-Fi** 的電腦。

```bash
npm install
npm start
```

終端機會印出「手機（同一個 Wi-Fi）」的網址。主持人用手機或電腦打開它、建立房間，其他人掃大廳的 QR Code 加入；3–10 人到齊後由房主按「開船！」。每局會抽新的故事卡。

**試玩方式（請至少連玩兩局）**
1. **第一局**是經典配置、丟掉的東西還撈得回來：先熟悉「丟東西 → 決定好了 → 黑暗補船 → 吃飯 → 衝向海灘」。
2. **第二局起**每局的見聞不同、風暴會捲走漂著的東西：開局請拿到「今晚你看到」卡片的人把它說出來，管倉丟東西前先問一圈。
3. 結尾會說「今晚靠的是……」；可以聊聊這局是誰的一句話最有用（不計分）。
4. 一個人想先看流程：開 `/solo.html` 可在同一個瀏覽器開多個座位。

- 自動測試：`npm test`（規則引擎、與 `tools/verify_seeds.py` 逐筆對照、多手機 WebSocket 整合測試）；瀏覽器端對端：`npm run e2e`（3／6／10 人各兩局，第二局會觸發風暴捲走）
- 規則試算：`python3 tools/verify_seeds.py --table`（列出全部通過的「起風卡×見聞」與允許的風暴卡）
- 型別檢查：`npm run typecheck`
- 伺服器重開會清掉所有房間；這只是區域網路原型（見 docs/adr/0004）。
