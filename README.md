# 不可能的任務｜Impossible Mission

> 手機只是工具，真正的冒險發生在人與人之間。

**專案狀態：遊戲企劃／待製作 MVP（截至 2026-11-13）**  
**暫定產品名稱：** 不可能的任務（英文代號 `impossible-mission-bible-game`）  
**對象：** 教會小組、青少年與成人；對聖經不熟悉、尚未信主的朋友也能直接參與。

## 核心目標

- **3–10 人**同場合作，每局**5–10 分鐘**，一局結束可以直接再玩一局。
- **每人一支手機，掃 QR Code 加入；不安裝 App、不登入帳號；不使用額外卡片或道具**。
- 以**面對面討論、交換情報、協商決策、互相協助**作為主要遊玩內容；手機用來顯示每人的情報／功能、同步事件、倒數與驗證結果。
- **可以互看對方手機、自由說話**；不以禁止交流、要求每個人記密碼、監督行為作為遊戲規則。
- 遊戲先要好玩，最後才用一段短而準確的聖經連結，引導玩家認識神及彼此。
- 沒有強迫自我揭露、羞辱或信仰分數；避免用沉迷機制推動反覆遊玩。

## 第一個遊戲：暴風雨救援（設計稿）

救援隊要在暴風雨中，根據有限資訊選擇可通行路線、準備符合需求且未超重的物資，應對**吊橋崩塌＋停電**，恢復通訊後提交最終救援方案。

- **導航員：** 看路線與時間、決定路線。
- **補給員：** 選擇物資與計算載重。
- **通訊員：** 掌握村民需求與通訊編號。
- **工程師：** 緊急修復系統／輸入備援代碼。
- **醫護員：** 確認物資是否符合需求。
- **觀測員：** 掌握天候與洪水限制。

角色資料可以互相分享或直接展示；各角色只有不同**功能與資訊視角**，不是禁止別人看畫面。

### 一局簡表（目標 8 分鐘）

| 時段 | 發生的事 | 玩家實際互動 |
| --- | --- | --- |
| 0:00–1:00 | 進房間、自動分配角色 | 與隊友認識角色、開始交換線索 |
| 1:00–3:00 | 擬定救援計畫 | 面對面比較路線、需求、重量，完成初步方案 |
| 3:00–5:00 | 吊橋崩塌、停電 | 緊急重新討論，工程師以隊友情報解鎖備用電力 |
| 5:00–7:00 | 修訂並送出方案 | 變更路線與物資，通過系統驗證 |
| 7:00–8:00 | 結果、聖經連結 | 說出隊友的貢獻，聆聽經文與簡短問題 |

> 時間是首輪設計目標，不是已經實測通過的結果。實作須能讓提前過關的隊伍直接結束，超時亦有友善收尾。

## MVP 原則

1. **先做一關完整可玩，不是只做展示頁。** 多人進房、同步狀態、角色操作、事件、答案驗證、結局皆可測試。
2. 手機上的**路線卡／物資卡**替代一切實體卡片；沒有必須自行列印的東西。
3. 突發停電是**遊戲網頁遮蔽正常情報**，不是把手機真的斷電；工程師備援面板可用。
4. 不要用硬性「雙人核准」替代有趣的合作；只有當信息確實需要交叉比對時，才有意義。
5. **3 人到 10 人**全部應能開局並有可做的事情；人數調整方式見任務規則。
6. 未取得實測證據前，不宣稱遊戲已上線或達成留存、好玩度指標。
