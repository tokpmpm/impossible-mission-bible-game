# 聖經結合與內容審核（v0.3）

## 核心原則
遊戲要先讓不熟悉聖經的人也覺得有趣，並且透過真人互動認識彼此。聖經不應變成解謎門票或考核信仰高低的工具。

**v0.3 做法：經文先做成機制，讓玩家「玩的時候就經歷到」，結尾只需揭曉「你們剛剛做的就是這段經文」。** 反思回應玩家真實經歷的合作，而不是硬套一段經文。

## 第一關：哥林多前書 12:12–27

### 經文重點 → 遊戲機制
（經節內容以非逐字摘要表示，正式文案須確認譯本授權並經人工審核。）

| 經文重點（摘要） | 對應機制 |
| --- | --- |
| 身體有許多肢體，卻是一個身體（12–14 節） | 六個角色各持不同資訊，任一人都無法獨自完成 |
| 眼不能對手說「我用不著你」（21 節） | 危機時隨機一位「受困角色」面板全黑，要靠隊友口述才能操作 |
| 看似軟弱的肢體更是不可少的（22 節） | 開局匿名猜「這局誰會是關鍵角色」，系統讓最少人猜到的角色握有突破口關鍵線索 |
| 不體面的，越發給他體面（23–24 節） | 結尾每人都有專屬稱號，沒有排名、沒有人落空 |
| 一個肢體受苦，所有肢體一同受苦（26 節） | 過載機制：有人任務堆積時全隊倒數加速；按「求救」後大家能分擔 |
| 你們就是基督的身體，並且各自作肢體（27 節） | 結尾「身體拼圖」把本局角色拼成一個身體 |
| （延伸）我們不是全部 | 沒送到的村由「另一支救援隊」接手 |

## 結尾流程（約 2 分鐘，可跳過）
1. **結果**：顯示 ★ 星等與送達的村。沒送到的村顯示「另一支救援隊已接手」（多房間活動時顯示實際隊名）。拿 ★★ 時提示「還有一條路沒被發現」。
2. **自動回顧**：系統挑 2–3 個本局真實時刻，例：「停電時有 4 個人幫工程師描述符號」「小華按了求救，阿明接手」。
3. **感謝卡**：每人點選一位剛剛幫到自己的人；畫面只顯示「誰謝了誰」，不計票、不排名。
4. **專屬稱號**：每位玩家都拿到一個依實際行為產生的稱號（「關鍵一句話」「最穩的手」「求救勇者」）。
5. **身體拼圖**：角色拼成一個身體（觀測員＝眼、通訊員＝耳、工程師＝手、導航員＝腳、補給員＝肩、醫護員＝心），並把經節配上本局真實事件，例：「21 節 ← 小華的地圖全黑時，是阿明唸給他聽的」「22 節 ← 這局最出乎意料的關鍵角色是通訊員，突破口就在他手上」。
6. **一起聊聊（選一題即可）**：
   - 剛剛是哪位隊友的幫助，讓你改變了決定？
   - 我們選了先送哪兩村？那條被漏聽的訊息是誰的？
   - 你一開始覺得自己的角色重要嗎？現在呢？（對應 15–16 節，可只在心裡回答）
   - 在現實的小組裡，怎麼珍惜和自己不同的人？

## 建議結尾文案（示例）
**任務完成！**

剛才的救援沒有一個人知道全部答案，也不是靠某個人獨自完成。有人找路、有人注意危險、有人記得村民的需要、有人修復設備——還有人在看不見的時候，靠別人的聲音完成任務。

保羅在哥林多前書第 12 章談到，一個身體雖有許多不同的肢體，卻彼此相關、不能彼此輕看。

## 往後關卡的設計方法
每關**先選經文，再從經文重點推出機制**，例：
- **五餅二魚**：資源越分享越多，囤積反而減少。
- **尼希米修城牆**：一手修牆一手守望，要同時顧兩件事並互相掩護。

## 內容查核
- 聖經引述須確認譯本和著作權；若無授權，先採經文位置與非逐字摘要。
- 人工審核經文上下文、神學意涵與遊戲比喻是否恰當（含「身體拼圖」部位對應）。
- 不要求非基督徒公開個人宗教立場。
- 不將玩家的善行、答題速度或競賽結果換算成信仰分數；星等只描述任務結果。
- 「猜關鍵角色」不顯示票數、不出現「不重要」等字眼；揭曉以驚喜的正面方式呈現，文案須測試。
- 引導最多約 2 分鐘，可選擇略過或由主持人自然延伸。
