# 測試與驗收計畫

## 目標
驗證《不可能的任務》是真的可供 3–10 人以各自手機共同玩的遊戲，而不是僅有單人可點擊畫面的 Demo。驗收同時涵蓋遊戲邏輯、多人同步、手機 UX、現場氣氛及聖經連結。

## 邏輯測試
- 各條路線的通行時間和洪水限制。
- 每種物資重量與總重計算。
- 危機前後各組合的星等是否符合 `02-MISSION_01_STORM_RESCUE.md` 示範種子。
- 斷線、重連、重試、快速重複提交、遲到玩家及主持人離線。
- 角色在 3、4、5、6、7、8、9、10 人時的分工合理性。

## 現場試玩
每種人數至少測一場，重點看：
- 是否能在 5–10 分鐘內結束，還是變成長時間等待？
- 參與者是「抬頭互相討論」還是只剩個人低頭點按？
- 是否每一位玩家都說過話、提供過資訊或進行操作？
- 停電發生前，玩家是否有真正可被改變的計畫？
- 描述型修復是否讓每位玩家都開口？喊話混亂期是否好笑而非過載？
- 多數隊伍是否拿到 ★★？是否有人發現 ★★★ 突破口？拿 ★★ 的隊伍是否想再玩？
- 「猜關鍵角色」揭曉時，被揭曉的人是否覺得是驚喜而非被看輕？
- 結尾經節配對是否讓未信主的朋友覺得自然、看得懂？
- 聖經環節是否自然、正確、不造成非教友壓力？
- 玩家是否願意不被催促就繼續玩下一局？

## 驗收紀錄
每次測試記錄：日期、版本、參與人數、設備／瀏覽器、實際耗時、成功率、錯誤、玩家觀察與後續修正。沒跑過的項目標記「未測試」，不得自稱通過。
