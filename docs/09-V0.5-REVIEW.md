# v0.5 設計 PR 審核清單

> 只改文件並新增一支規則試算腳本；沒有遊戲程式，也沒有真人試玩。

## 這版改了什麼
| 項目 | v0.4 | v0.5 |
|---|---|---|
| 常規路線 | 紅、藍工具都是 2 kg，危機只是換工具 | 工具重量不同；危機後原方案裝不下，要決定放下什麼 |
| 危機 | 選哪條就封哪條 | 每個種子固定危機；最晚 2:45 觸發 |
| 可連玩 | 只有 seed 001 | 加入 seed 002（P0） |
| 停電修復 | 工程師＋三位隊友 | 每位非工程師都有符號或排除線索 |
| 符號 | 清楚區別 | 相似但以外形、缺口數、方向區分 |
| 偏好題 | 「額外提示」未定義 | 一次「排除兩個錯誤符號」 |
| 關鍵角色 | 移除投票 | 不投票；突破口起點每局輪替職能 |
| 結尾 | 事件回顧與經文分開 | 真實事件直接配經節；加點選感謝卡 |
| 未定義規則 | 2:45 未鎖定、零村出發 | 皆已定義 |

沿用 v0.4：三次高潮、停電只做一件事、故事時間與真實倒數分開、二星看急迫需求、完整隨機產生器延後。

## 規則試算結果
執行 `python3 tools/verify_seeds.py`，窮舉每條路線的所有裝載組合。兩個種子都通過以下七項：
1. 危機前，預定路線排得進三村。
2. 危機前，另一條常規路線最多二星。
3. 危機前，綠線不可行。
4. 危機後、沒用突破口，最高二星。
5. 危機後，剩下的常規路線有二星解。
6. 危機後用了突破口，綠線三星。
7. 三星只來自綠線。

## 需要 Reviewer 特別看
- 開局的「三村方案」只有一條路排得進去，等於開局有正解。找不到的隊伍（選了另一條路）危機時路線沒被封，轉折感較弱；是否可接受要看實測。
- 「排好的計畫被打亂」可能讓人更投入，也可能讓新朋友挫折。
- seed 001 與 seed 002 結構相同（預定路線被封→綠線突破口）。玩兩局後可能看出套路；seed 003 應換結構。
- 4 個符號 60 秒與排除線索是否過載；5 人以上的排除線索文案需逐條確認不會互相矛盾。
- 經節對應表是體驗上的呼應，需由懂聖經的人審核用詞與上下文。
