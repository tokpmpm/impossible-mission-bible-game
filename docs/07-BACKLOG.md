# MVP 開發待辦與驗收條件

## P0｜做出第一個真正能玩的多人關卡
- [ ] **US-01 建立與加入房間**：主持人生成 QR Code，3–10 人免帳號以暱稱加入。
- [ ] **US-02 角色分配**：每位玩家有重要線索或功能；3–5 人可兼任角色，7–10 人不得當純旁觀者。
- [ ] **US-03 多角色任務面板**：導航、補給、通訊、工程、醫護、觀測各有不同資訊；可自由展示手機。
- [ ] **US-04 共享狀態**：路線、物資、重量及危機即時同步；伺服器是唯一真實狀態。
- [ ] **US-05 危機事件**：吊橋坍塌與停電只觸發一次，遮住主要情報但不斷線、不阻止交談。
- [ ] **US-06 備援解鎖**：工程師和隊友合作推導密碼（示範 257），驗證成功後所有人畫面恢復。
- [ ] **US-07 最終救援**：後端驗證路線、物資、重量、時間、電力狀態，成功／失敗回饋一致。
- [ ] **US-08 聖經結尾**：哥林多前書 12:12–27 的短引導與可選分享，隨時能進下一局。
- [ ] **US-09 房間重連**：短暫離線可恢復角色與進度，不需全部玩家重來。
- [ ] **US-10 倒數與超時**：伺服器計時、超時收尾與重新遊玩。

## P1｜體驗與品質
- [ ] 手機 320px 寬畫面、觸控尺寸、對比與字幕檢查。
- [ ] 房主離線、玩家切換背景與網路抖動的處理。
- [ ] 簡潔音效及震動（可關閉），低動態模式。
- [ ] 精緻桌遊／救援主題視覺，無需幼稚風格。
- [ ] 3、6、10 人現場試玩，記錄討論時間、完成時間、投入感。

## P2｜重玩性
- [ ] 不同路線、天候、負載與村民需求生成可解的任務變體。
- [ ] 不同危機：通訊故障、載重限制變更、臨時醫療需求。
- [ ] 新的原創關卡與對應聖經主題，經人工作內容審核。
- [ ] 關卡生成器需有解題驗證器，避免無解或多解造成挫折。

## 暫不做
原生 App、付費商城、排行榜、每日打卡、AI 自動寫未經審核經文、大量先做沒有實測的關卡。

## 定義完成（DoD）
完成不等於「程式碼已寫」，必須能讓 3–10 人真實加入同一房間，完成一次救援、同步事件、修復、結算與下一局，附可重現測試結果。若 UI 好看但多人不能玩，仍屬未完成。
