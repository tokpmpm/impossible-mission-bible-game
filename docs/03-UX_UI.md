# 手機 UX／視覺設計建議 v0.1

## 核心原則
- 每人手機瀏覽器即可玩，不用下載 App、不註冊帳號，也不用準備其他卡片／道具。
- 介面吸引青少年與成人：**精緻桌遊＋冒險派對**，深藍、暖金、清楚的情境插畫；不是幼兒教具。
- 讓人盡量抬頭彼此討論，不要用大量表單、重複簽核阻礙現場互動。
- 大字、清楚的主行動區、單手可操作、文字／圖示雙重提示；不強制音效或站立。

## 玩家流程
1. 主持人「建立房間」→ 取得 QR Code 與房號。
2. 玩家掃碼加入→ 輸入暱稱 → 等待 3–10 人。
3. 系統分配各自的角色、線索與操作能力。
4. 主持人開始→ 角色分工與救援決策。
5. 事件發生→ 全員同步收到危機／停電畫面。
6. 工程師操作備援、其他人提供資訊。
7. 全隊修正路線與物資→ 提交救援。
8. 顯示結果、聖經反思→ 下一局。

## 主要角色頁面
**導航員**：可選紅線／藍線／綠線；顯示耗時、必要工具及通行狀態；預先選定路線不等於過關。

**補給員**：可點擊物資卡；即時顯示救援車載重上限（示範 6 kg，隨機 5–7 kg）、目前已裝哪些物資與可送達哪些村。無須使用桌上卡片。

**通訊員／醫護員／觀測員**：不同重要線索，可按「放大給隊友看」，保留面對面分享感。

**工程師**：正常時備用電源待命；停電時顯示 9 個相似符號，依隊友口述依序選出。

**按住才顯示**：修復符號等線索按住才出現、鬆手消失，讓口頭描述比搶手機更快；不禁止互看。

## 停電的呈現方式
- 系統同步把遊戲內正常情報改成遮罩，顯示「紅線吊橋坍塌，供電中斷」。
- 倒數、事件說明、如何協助工程師始終可見，不讓玩家黑屏無事可做。
- 工程師的備援功能不被遮住；全員可繼續交談、互看手機。
- 修復成功後，全員畫面即時恢復。
- 保留大字模式、低動態模式及可靜音設計。

## UX 驗收重點
- 320 px 寬手機不溢出；主要按鈕有足夠觸控尺寸（目標至少約 44 px）。
- 不能只靠顏色傳達警報；圖示與文字必須一起提示。
- 網路斷線、重連、超時、通關與新回合，都要有清楚且不混淆的畫面狀態。
- 正常資訊不能在停電時仍可透過未遮蔽的頁面誤用（但不可阻止玩家靠記憶或口語協助）。
- 原型需在真實手機／多人現場測試，不可只在桌面寬螢幕看起來好看。
