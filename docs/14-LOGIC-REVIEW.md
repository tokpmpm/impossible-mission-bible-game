# 第一關「保羅海難」故事邏輯審查（2026-11-20）

> **白話摘要（5 行）**
> 1. **「沒吃飯為什麼也有力氣？」**現在的規則是：今晚的食物「留在船上」就算力氣顧好了，不一定要吃。試算 262 種局面，有 **145 種（55%）不吃飯也能拿三星**；只有一張故事卡（B5）規定要真的吃。這跟經文（27:33–38，十四天沒吃，吃了才放心）對不上，是這次最嚴重的問題。
> 2. **「有機會不能平安上岸嗎？」**不會。規則裡每一局都上岸，結算畫面也一定寫「船上 276 人，全都得救上了岸」。但標題只有二星才叫「平安上岸」、零星叫「大家**還是**都上了岸」，沒顧到的事寫「船尾被打得更碎」等，會讓人以為星星少就是不平安。要改用字，不用改規則。
> 3. 另外找到 14 個比較小的不合理處，例如「大家暈船吃不下，食物帶上岸再吃」（經文是大家都吃了）、「船上 276 人所以糧食變重」（人數一直都是 276）、補船畫面寫「船只能留 4」但實際是 5。
> 4. 建議一套整體修正（V5）：**力氣只能靠吃飯；吃飯是全船一起、不佔「只來得及一件」；危機後載重 5→4；拿掉「吃不下」；B3 改成「吃飽了把麥子拋在海裡」**。試算：全部局面都有三星解、照抄成功率 17.8%（仍低於 20% 的門檻）。
> 5. 這是**審查與設計提案**：沒有改遊戲程式（src／public／tools 都沒動），沒有真人試玩。最後有 3 題請使用者決定。

狀態：AI 審查（2026-11-20），以分支 `feat/scoring-leaderboard`（含 PR #19、#21、#22）為準。經文依和合本神版（DECISIONS 14）；引文已在 `tools/verify_verses.py` 核對過的範圍內，本文新增的經文引用只附章節、未另行逐字核對。試算腳本：`python3 docs/appendix/logic_review_sim.py --dist`（約 3 秒；V0 重現 `tools/verify_seeds.py` 的 64／262／13.5%／19.1%／27.5%，才拿來比較）。

## 1. 使用者的兩個問題

### 1.1 「沒吃飯為什麼也可以有力氣？」

**現在規則怎麼運作**
- `src/engine/rules.ts:108`：某件事算顧好＝「卡片已顧好」**或**「今晚的那樣東西還留在船上，且這件事不在 `eatOnly` 裡」。
- `src/engine/seeds.ts:81–83`：力氣今晚靠 `糧食` 或 `麥子`（見聞「食」）。所以**糧食留在船上＝力氣顧好**，不必按「召集大家吃飯」。
- 吃飯（`USES.吃飯`）只是三種「用掉」之一：吃掉食物讓它不佔重量，換取空間留別的東西（docs/11「補好船後」、`content.ts:73`「用掉就輕了」）。
- `eatOnly: ['力氣']` 只有 **B5** 一張卡有（`seeds.ts:95`，卡面寫「大家已經餓了十四天：留著食物不夠，要真的吃」）。
- 見聞「胃＝吃不下」時根本不能吃飯（`seeds.ts:33`），文字是「食物要帶到上岸再吃」（`content.ts:100`），也就是規則**鼓勵把食物帶上岸**。

**為什麼會這樣**：v0.7 的設計（DECISIONS 2026-11-15 第 2 條）把吃飯當「突破口」——危機後載重變小，吃了糧食船才輕得夠。重點在「吃了船就輕」，力氣本身用「留著就算」來表示。v0.8 加入「三種用掉只來得及一件」後，吃飯變成三選一，留著食物、改拋錨或捆船底常常一樣三星。

**試算**（`logic_review_sim.py`，V0 欄「不吃飯也三星的局面」）：262 種局面中 **145 種**存在不吃飯的三星打法；首局經典配置（糧食／纜索／深／吃得下）因為水深不能拋錨，最好的打法剛好是吃飯，所以第一局看不出問題，第二局起就會出現。

**玩家怎麼理解**：畫面上「🍞 力氣」在留著糧食時就亮了，玩家自然推論「船上有吃的＝有力氣」，然後發現沒吃也過關，就會問這個問題。更糟的是 B5 那局突然說「留著不算」，玩家會覺得規則前後矛盾。

**跟經文哪裡對不上**
- 27:21、33：「眾人多日沒有吃甚麼」「你們懸望忍餓不吃甚麼已經十四天」——有食物、但沒吃，所以沒力氣。經文裡**有食物不等於有力氣**。
- 27:34–36：保羅勸大家吃飯「這是關乎你們救命的事」，大家吃了才「放下心」。
- 27:38：「吃飽了，就把麥子拋在海裡」——吃在前、拋在後。
- 27:43–44：上岸是游水、抱板子，食物不可能「帶上岸再吃」。

**建議修法**：見第 3 節 V5（力氣只能靠吃飯，且吃飯不佔「只來得及一件」）。

### 1.2 「有機會不能平安上岸嗎？」

**現在規則怎麼運作**：不會。每一局的結局都是全船上岸——
- 正常出發：`game.ts settle()` 給星等；時間到（8:00）若還在黑暗中或超重，`phase='ended'`、沒有星等，結算照樣顯示（`game.ts:355–363`）。
- 結算畫面一定有「船上 276 人，全都得救上了岸（徒 27:37、44）」（`public/app.js:936`），這局重播最後一行一定是「船擱淺了，大家有的游、有的抱著板子，都上了岸（27:41–44）」（`room.ts:945`）。
- docs/11「不違背經文的界線」與 DECISIONS v0.7 第 1 條也明定沒有「有人死掉」的失敗。

**為什麼玩家還是會這樣問**（用字暗示「可能不平安」）：
| 位置 | 現在的字 | 為什麼會被誤會 |
|---|---|---|
| `room.ts:853` 結算標題 | 3「上岸很順利！」2「**平安上岸**」1「上岸了，有點狼狽」0「大家**還是**都上了岸」 | 「平安上岸」只給二星 → 一星、零星好像不平安；「還是」像是差點沒上岸 |
| `public/app.js:378` 首頁副標 | 「一起讓全船平安上岸」 | 把「平安上岸」說成玩家要達成的目標，等於暗示可能失敗；而且經文裡是神應許（27:22–24），不是船員做到的 |
| `room.ts:937–941` 沒顧到的事 | 「上岸時大家游得很吃力」「船尾被浪打得更碎」「夜裡差點撞上礁石」 | 「差點撞上」像在說差點出事；「船尾更碎」——經文裡船尾**本來就**被打壞（27:41），顧好船身也一樣 |
| `content.ts:60` 船長線索 | 「超過就會進水」 | 像是船會沉；實際規則只是「不能出發」 |
| 計分 `room.ts:881` | 「任務成果 600：顧好 N 件」 | 零星＝任務成果 0，像任務失敗 |
| 卡 A1 經文 | 「連我們的性命也難保」（27:10） | 這是保羅開船前的話；後來他說「性命一個也不失喪」（27:22），但 B4 不一定同局出現 |

**跟經文的關係**：經文沒有改寫，結局正確；問題在**用字讓星等看起來像「平安程度」**。DECISIONS／AGENTS「不改寫經文結局」要求的不只是規則，也包括玩家的理解。

**建議修法**（只改文字，不影響 `tools/verify_seeds.py`）
1. 結算標題一律以「全船平安上岸」開頭，星等改成形容**這一路**：3「全船平安上岸・一路準備周全」、2「全船平安上岸・準備了大半」、1「全船平安上岸・這一路很辛苦」、0「全船平安上岸・這一路非常狼狽」。276 人那行移到標題正上方、字級放大。
2. 首頁副標改為「保羅海難：每人一支手機，一起把船上的事顧好」。
3. 沒顧到的事改成只描述「辛苦」、不描述「險些出事」：力氣「沒吃飯，大家游上岸時很吃力」；船身「船散得早，更多人抱著板子上岸（27:44）」；天亮「沒拋好錨，大家在黑夜裡提心吊膽到天亮」。
4. 計分「任務成果」改名「上岸準備」（分數、公式不變；DECISIONS 17 的 600 分不動）。
5. 船長線索改「超過了船吃水太深，不能開船」。
6. 星星本身改稱「上岸準備 N／3」（GLOSSARY「星等」定義改為「上岸時三件事準備好幾件；不代表有沒有人得救」）。

## 3. 整體修正方案（建議 V5）

### 3.1 規則
1. **力氣只能靠吃飯**：全域 `eatOnly: ['力氣']`；「今晚的食物」要在補好船後還在船上，伙房按「召集大家吃飯」才顧好力氣（27:33–36）。
2. **吃飯是全船一起，不佔「只來得及一件」**：天亮前另外**只來得及再做一件**——拋錨（水淺才行）或捆船底。突破口線索改成「吃了才有力氣；吃完之外，天亮前只來得及再做一件」。
3. **危機後載重 5→4**：讓「吃完以後還要不要拋錨／捆船底」重新變成取捨（只改 1、2 的話吃完直接剩 5，留纜索＋錨剛好，沒有決定可做——見 V1）。
4. **拿掉見聞「胃」**（「吃不下」與 27:33–36 相反）；「食」改給醫生（U5）。
5. **B5**：只剩「錨已拋下：天亮顧好、錨離船」，拿掉 `eatOnly`、`exclude`。
6. **B3**：「船上共有 276 人。吃飽了，就把麥子拋在海裡」（27:37–38）：麥子自動離船；不和「今晚靠麥子」同局。
