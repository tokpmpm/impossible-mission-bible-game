# 關卡改用聖經故事背景，加入故事卡

Status: accepted（2026-11-15 使用者決定方向；數值與卡片效果為 AI 設計提案，未經真人試玩）

## 背景
使用者 2026-11-15 決定：「老智慧」不有趣，整個拿掉；改以聖經故事當關卡背景，第一關改編保羅海難（徒 27），並加入「故事裡真的發生的事」做成的故事卡，讓同一關重玩也不一樣。

## 決定
1. **一關＝一段聖經故事**。第一關 `ship 001`：使徒行傳 27 章。原創的暴風雨救援 seed 001／002 從引擎、房間、前端與 `tools/verify_seeds.py` 移除，只留在 git 歷史與 docs/02。理由：兩套規則一起維護的成本高，且使用者已確定取代。
2. **結局不可改寫**。經文裡全船得救，所以規則裡沒有失敗結局；星等衡量「上岸順不順」（三件事顧好幾件）。玩家只做船員做得到的事，不操作神蹟。
3. **規則模型改為「留什麼」**：所有東西一開始都在船上，留下的總重 ≤ 安全載重才可「決定好了／衝向海灘」；星等＝顧好的件數。原本的路線、工具、故事分鐘、安全窗、急迫村全部拿掉（經文裡船「敵不住風，任風颳去」，沒有航線可選）。
4. **故事卡是資料，不是程式分支**：每張卡只能用少數幾種效果（重量增減、自動離船、已顧好、危機前釘住、時間偏移、線索公開）。前四種影響可解性，必須寫進 `tools/verify_seeds.py` 並對所有組合試算；後兩種只影響節奏。引擎仍是純函式，與腳本逐筆對照（ADR-0002 不變）。
5. **抽卡時機固定**：開局一張（起風）、補好船一張（風暴）。抽到哪張由房間層決定（同房間盡量不重複上一局），引擎只收卡片代號。
6. **操作只顯示給負責的人**（取代 ADR-0003 第 25 條附近「非操作者也顯示按鈕」的做法）；伺服器仍會拒絕非負責人的操作。

## 後果
- 新增卡片或新關卡時，先改 `tools/verify_seeds.py` 並通過，再改 `src/engine/mission.ts`，`test/golden.test.ts` 會逐筆比對。
- 第二關（尼希米修城牆，PR #17）可沿用同一套「故事卡＋資料化效果」。
