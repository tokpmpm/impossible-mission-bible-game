# 規則引擎是純函式，並以 verify_seeds.py 的窮舉結果作為對照檔

Status: accepted（暫定，可在 /to-spec 時調整）

引擎寫成「目前狀態＋一個事件（含已經過的房間倒數毫秒）→ 新狀態」的純函式，不自己讀時鐘、不連網路；2:15、2:45、修復逾時都由呼叫端把時間當成事件送進來。規則結果與 `tools/verify_seeds.py` 的一致性，靠讓腳本匯出「每個種子 × 危機前／危機後／危機後＋突破口 × 每條路線 × 每組物資」的星等與第一個拒絕原因成對照檔，引擎測試逐筆比對。

為什麼：AGENTS.md 要求結果須與腳本一致，而遊戲預計用 TypeScript（04-MVP_TECH），腳本是 Python。只比腳本印出的「每條路最佳解」太粗，逐筆窮舉比對才抓得到邊界錯誤；時間由外部注入，F05（2:45 未鎖定）、F08（逾時）、F27（2:15）才能不等真實時間就測。

## Considered Options
- 引擎也用 Python、直接 import 腳本：省事，但遊戲伺服器是 TS，最後仍要重寫一次。
- 把種子資料抽成共用 JSON 給兩邊讀：更乾淨，但要改動腳本結構；留待新增 seed 003 時再評估。

## Consequences
- 腳本把工具當成可選物資；引擎讓工具隨路線自動上車（見 ADR-0003）。比對時只取「物資組合中恰好帶當前路線工具、沒帶其他工具」的那些筆，兩者等價。
- seed 002 工具名稱腳本寫「繩子／燈具」，文件寫「長繩／頭燈」；對照檔以腳本為準、顯示用文件名稱，之後再統一。
