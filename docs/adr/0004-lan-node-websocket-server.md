# 原型用自架的區域網路伺服器，不用 Supabase

Status: superseded by ADR-0005（部署方式）；Node 版仍可在本機或區域網路使用

第一個可玩原型用一支 Node 伺服器（WebSocket＋靜態檔）在主持人的電腦上執行，手機連同一個 Wi-Fi 掃 QR Code 加入。房間狀態只在伺服器記憶體裡，伺服器是唯一權威，規則交給 src/engine。

為什麼：docs/04 建議的 Supabase 需要帳號與金鑰，使用者不在時無法取得；而 3–10 人同一個房間面對面玩，區域網路就夠。伺服器權威、單執行緒處理動作，也讓「危機只觸發一次、結算只一次、重送不重複」容易保證。

## Consequences
- 伺服器重開，進行中的房間就消失；玩家需要重新開房。
- 要讓不同地點的人玩、或部署到網路上，之後要換成有持久化的後端；換的時候 src/engine 不用動，只換 src/server。
- 前端不打包、不用 CDN，沒有網路的教會場地也能跑。
