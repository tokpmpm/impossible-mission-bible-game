# 遊戲設計概要 v0.4（提案，待 PR 審核）

## 核心目標
不可能的任務是一款 3–10 人同場合作的手機破冰遊戲。正式計時一局 8 分鐘（允許 5–10 分鐘彈性），掃 QR Code 入房時間不計入。玩家不用懂聖經也可參與；最後以 60–90 秒自願分享連結哥林多前書 12:12–27。

**硬性限制**：只用各自手機、不需要卡片或其他道具；可以互看手機、自由說話、不強制站立；任務互動要以面對面對話為主，而非連續點選「同意」。

## 每局的三次高潮
1. 交換資訊，提出暫定救援方案：不只讀線索，要做有代價的取捨。
2. 方案受危機影響，進行 **45 秒、單一焦點** 的合作修復；不疊加其他倒數任務。
3. 重整策略，發現三段情報構成的隱藏突破口，爭取最佳救援結果。

## 認識人的機制
- 入房後可選答一題無壓力偏好（例如「旅行排滿行程／隨性走走／都可以」）；可跳過。
- 偏好答案只用於一項 **非必要的提示或獎勵**：「找出哪位隊友是隨性派」。有多位同答案就由系統指定其中一人，沒人符合或全員跳過則自動轉為指定玩家的中性線索。
- 需要隊友說出自己的選擇與原因；不得強迫談隱私、信仰或傷痛。偏好線索不作為通關的唯一必要條件。
- 每局至少交換一次夥伴；結尾邀請大家說出一件剛剛認識隊友的新事情。

## 角色（六種能力，不代表只能六個人玩）
導航：路線選擇。補給：物資裝載。通訊：村莊需求與通報。工程：備援修復。醫護：急迫需求排序。觀測：天候與安全窗。操作權是入口分工，不是禁止他人查看資料或討論。

### 3–10 人具體分配
| 人數 | 角色安排 |
|---|---|
| 3 | 導航＋觀測／補給＋醫護／通訊＋工程 |
| 4 | 導航＋觀測／補給／通訊＋醫護／工程 |
| 5 | 導航／補給／通訊／工程／醫護＋觀測 |
| 6 | 六項各一人 |
| 7 | 在六職能上拆出「道路偵察」；偵察員持有危機後替代路的關鍵狀態 |
| 8 | 再拆出「村民聯絡」；聯絡員掌握東、西、北村的最新需求優先順序 |
| 9 | 再拆出「倉儲管理」；倉儲員掌握工具存量與備用裝備的取用操作 |
| 10 | 再拆出「備援觀察」；觀察員掌握修復面板的一個判別線索與協作操作 |

7–10 人時 **資訊從原職能拆出**，不額外增加第二套難題；這四個職能的線索與操作必須真的影響原本決策，不可只是裝飾。每人至少有一項有效線索或有意義的操作；角色不應集中在單一大聲玩家。

## 成功與失敗
- 三星：三村今晚需求都送到（要發現隱藏突破口）。
- 二星：先送到兩個真正急迫的村（東村藥品、西村飲水）。
- 一星：有合法救援成果但未滿足上述優先組合。
- 路線、重量或電力不合法：拒絕出發並顯示可修復錯誤，不以失誤羞辱玩家。
- 遊戲的「洪水時間」是**故事世界的行車安全門檻**，不是手機上逐秒消耗的真實倒數；兩者分開顯示與計算。

## 重玩與節制
MVP 先設計一個完全驗證的固定情境（seed 001）；再人工設計另外兩個變體並通過邏輯驗證與真人試玩。完整隨機產生器留到第二階段；不做排行榜、連續登入獎勵或信仰高低評價。
